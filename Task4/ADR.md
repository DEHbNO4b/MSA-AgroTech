### <a name="_qmphm5d6rvi3"></a>**Решение**
Решение
1. **Архитектурный стиль**
Выбран микросервисный подход с разделением системы на два уровня:
Edge-уровень (фермы):
автономная работа, управление оборудованием, локальные события.
Центральная платформа:
аналитика, ML/AI, BI, отчёты, интеграции, IAM.
Это обеспечивает автономность ферм + централизованную аналитику.
2. Сравнение вариантов Вариант 1 — Edge-heavy
Edge выполняет:
видеоаналитику,
локальные уведомления,
SCADA управление,
публикацию в Kafka.
Вариант 2 — Central-heavy
Edge:
только сбор и хранение данных,
минимум логики.
Центр:
основная аналитика,
видеообработка,
корреляции событий.
3. Итоговое решение
Принят гибридный подход на основе Edge-heavy (вариант 1), но с возможностью уменьшать вычислительную нагрузку на edge для экономичных ферм.
Обоснование выбора:
Без связи ферма должна функционировать полностью.
Видеоаналитика критична и требует минимальной задержки.
Kafka упрощает масштабирование и сервисную интеграцию.
Edge-хранилища предотвращают потерю данных.
4. Основные компоненты
Edge
Sensor Collector (Go)
Video Collector (Go) + Video Analytics (Python/OpenCV)
SCADA (Ignition)
Feed & Water Control Service (Go)
Local Notification Service
Edge Data Lake / Mini-DWH
Edge API Gateway (если используется схема V2)
Центр
Kafka (шина данных)
Data Lake (MinIO)
DWH (ClickHouse)
ML/AI Analytics (Python/Spark)
Central Notification Service
Web Portal (React)
Mobile App (Flutter)
BI (Power BI)
IAM service
Альтернативы
Альтернатива 1: Cloud-only
Плюсы:
Минимальные требования к edge
Легкие обновления ML
Минусы:
Высокая задержка
Полная зависимость от сети
Невозможность SLA < 5 сек
Альтернатива 2: Edge-only
Плюсы:
Максимальная автономность
Быстрые реакции на события
Минусы:
Трудно обновлять ML модели на местах
Нет централизованной отчетности
Высокие затраты на оборудование
Альтернатива 3: Serverless + централизованный ML
Плюсы:
Простое масштабирование
Минусы:
Непригодно для оффлайн-ферм
Не подходит для видеопотоков
Недостатки, ограничения, риски
Высокая сложность управления Edge-серверами — нужны централизованные обновления, мониторинг.
Повышенные требования к железу на ферме — GPU/CPU для ML.
Проблемы синхронизации при нестабильной сети — нужны очереди, буферы.

Безопасность — Edge физически незащищён: VPN, disk encryption, hardened OS.
Нагрузка на Kafka — требуется кластерная конфигурация и мониторинг.
Обилие распределённых сервисов — необходимость единой observability-стратегии.
